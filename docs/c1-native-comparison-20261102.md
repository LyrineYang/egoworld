# C1 原生产品管线试验：2026-11-02

本轮已将比较推进到完整视频产品任务，并实际运行两条管线。EgoWorld 与未修改的 Data-Juicer 都从同一三帧 RGB 视频得到 **6 条有限的 21×3 手部预测**。本轮小样例中 Data-Juicer 的原生 CPU 管线更快。两端模型、预处理、手侧信息和额外输出不同，尚未达到严格同模型、同完整输出和同质量的 C1 核心验收条件，不计算框架加速比。

主要目标仍是 **Linux 单服务器 2–16 GPU**；本轮 RTX 4060 Laptop 8 GB 是补充环境，没有服务器扩展率结论。迁移配置与验收顺序见 [交接文档](handoff-server-comparison-20261102.md)。原始数据、日志和精确源码快照在 `/mnt/d/EgoWorld/runs/c1-comparison-20261102/`；[机器可读报告](benchmarks/c1-native-pilot-2026-11-02.json) 链接逐次记录及 SHA-256。

## 手部产品任务

| 本轮观察 | EgoWorld | 原生 Data-Juicer |
| --- | --- | --- |
| 完整路径 | CPU 清洗 → SAM2/DINO → HaMeR → Dex → QC/导出/提交 | 原生时长/分辨率/运动过滤、视频流去重 → WiLoR → 默认网格/可视化/JSON 导出 |
| 神经模型设备 | RTX 4060 CUDA | CPU Torch，原生设备判断为 CPU |
| 输入覆盖 | 同一冻结视频，3 帧 | 同一冻结视频，默认 frame_num=3，覆盖 3 帧 |
| 手部结构有效输出 | 6 行 | 6 行 |
| 本轮额外产物 | 9 个框、6 行 MANO 参数、3 行右手机器人映射 | 6 个 OBJ 网格、3 张可视化；元数据在默认 stats 副文件 |
| 子进程创建到退出墙钟 | 100.77 秒 | 61.18 秒 |
| 20 ms 采样进程树 RSS 最大值 | 8.49 GiB | 6.45 GiB |
| NVML 全设备显存最大值 | 7.21 GiB | 1.84 GiB |

全设备显存包含约 1.84 GiB 的桌面/其它进程基线，不能当模型独占显存。RSS 求和可能重复计算共享页。计时包括导入、输入处理、模型、导出与退出，排除测量外安装/下载和事后审计；OS 文件页缓存未清空。这是一次短样例观察，没有稳态吞吐、置信区间或质量优越性结论。

EgoWorld 使用已有服务器默认 `external_runner_mode=auto`，保持采样、精度和输出语义。先前本地 `per_task` 记录为 108.87 秒；两种模式的 boxes/hand_joints/hand_mano/robot_joints 全部逻辑字段精确相同。单次时延与观测条件不同，不把该差异写成消融收益。原始较慢记录仍保留。

Data-Juicer 未使用 `egoworld_stage_mapper`，没有 CPU→GPU 改写或模型替换；默认 `np=4`、`use_cache=true`、`skip_op_error=true`、`op_fusion=false`、`auto_op_parallelism=true` 均保留。WiLoR 默认三帧、batch=16、保存网格与可视化也未改。只指定输入、算子链及资产/输出位置。

WiLoR 算子本身声明支持 CUDA；本轮 CPU-only Torch 环境使原生判断返回 CPU。这不表示 Data-Juicer 只能用 CPU。服务器后续应另设官方 CUDA 环境组，保留其 CPU 清洗算子的自然设备策略。

EgoWorld 本样例使用人工确认的 instance ID/手侧映射，不能推广为自动手侧准确率；Data-Juicer 使用其检测器的手侧判断。结构有效仅表示所报告的数值形状/有限性及相应文件契约，不等于人工确认的准确姿态、物理米制手世界坐标或可用训练样本。

## 原生视频清洗

共同输入包含 1 个真实 RGB 片段和 **5 个明确标记的合成夹具**。预先定义任务为“保留唯一、可解码、有纹理的视频”；静止纹理在这一任务中应保留。它不是正式留出集质量评估。

| 输入 | 预先期望 | EgoWorld 默认清洗 | Data-Juicer 所选原生默认链 |
| --- | --- | --- | --- |
| 真实手部片段 | 保留 | 保留 | 保留 |
| 逐字节副本 | 拒绝 | 拒绝 | 拒绝 |
| 相同视频码流，仅容器信息变化 | 拒绝 | 保留，重复漏检 | 拒绝 |
| 损坏 MP4 | 拒绝 | 拒绝 | 拒绝 |
| 空白视频 | 拒绝 | 拒绝 | 拒绝 |
| 静止纹理 | 保留 | 保留 | 拒绝，默认运动阈值 |

EgoWorld 原始保留 3 条，其中符合本夹具任务的唯一可用项为 2；Data-Juicer 原始保留 1 条，唯一可用项为 1。EgoWorld 的容器改封装重复漏检必须补齐；Data-Juicer 默认运动阈值对静态场景的取舍应按所需数据类型配置。不能只按保留行数给清洗质量排名。

本次清洗墙钟为 0.65 秒和 12.52 秒。规则、统计采样/尺寸、启动成本及保留集合不同，仍不计算“相同工作量加速比”。Data-Juicer 的视频流去重已有可借鉴价值；EgoWorld 的逐输入拒绝理由与任务分支准入也应继续保留。

## C1 的其它实际产出与未完成范围

EgoWorld 场景任务得到 3 个相机和 18816 个点；独立 RGB-D/mesh 世界任务得到 3 个米制相机、3 个米制物体姿态和 5551 个世界点，正式导出与阶段提交通过检查。Fast3R 生产执行未固定随机视图编码，本轮点数差异不作为优化收益。

Data-Juicer 本轮只选择并运行了原生清洗/WiLoR 链，未运行其 MoGe/MegaSAM/HaWoR/动作分支。未运行不表示库中没有相应能力；不能把这张表当作整个 Data-Juicer 能力上限。完整三组对应输出矩阵、B2 至少五轮对照、C2 缓存/恢复以及独立质量留出集仍未完成。

## 失败记录与环境复现

所有首次失败和纠正后的结果分别保留，没有覆盖原报告：

- 原生 PyAV 16 已移除 `codec_context.close`，Data-Juicer 默认容错导致任务成功退出却零产出；外层非空验收捕获失败。固定兼容 PyAV 12.3 后重跑，未改算子源码。
- 原生手 Mapper 要求输入 `__dj__meta__`；补上纯来源 `input_id` 后，视频和模型未变。
- 新审计器最初只读主 JSONL，忽略原生默认 `_stats.jsonl` 中的预测；修正后复核原产物，并在最终整链重跑通过。世界导出的嵌套清单读取问题也修正并保留原审计失败。
- 初次观察器缺 psutil、PATH 缺 ffprobe，以及 NumPy/PyArrow 版本不兼容，均作为测量前准备问题留档。

独立 CPU 参考环境锁在 [requirements-native-c1.txt](../egoworld/experiments/requirements-native-c1.txt)，使用 Python 3.12、Torch 2.5.1+cpu、torchvision 0.20.1+cpu、NumPy 1.26.4、datasets 4.7.0、PyArrow 21、PyAV 12.3。Data-Juicer 固定 `09178e1e0ac76cfbfe11232d66244e1ccc5add6f`，372 个安装 Python 文件与该源码归档逐一匹配；WiLoR tracked 源码没有改动。运行产生的未跟踪 `__pycache__` 不是代码补丁。

新增服务器/审计门槛及既有阶段接口共 **19 项针对性检查通过**。生产包 Python 源码与既有 297 项回归/原生复现基线保持一致；不把旧回归数字说成本轮重新执行的测试。
