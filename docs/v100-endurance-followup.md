# V100 双卡长测复盘与 SAM2 解码优化

对照任务为 FreiHAND 图像编码的三帧 clip。两端使用相同冻结输入、清洗策略、模型、采样和输出契约。只有中间帧参与独立姿态评分。

## 从 96 到 864 张

| 计时段 | 96 EgoWorld | 96 Data-Juicer | 864 EgoWorld | 864 Data-Juicer |
| --- | ---: | ---: | ---: | ---: |
| 端到端墙钟 | 109.09 s | 178.26 s | 624.38 s | 921.29 s |
| 模型流水线 | 85.59 s | 154.21 s | 441.95 s | 730.39 s |
| 清洗筛选 | 12.72 s | 12.63 s | 111.62 s | 113.06 s |
| 提交后校验与导出 | 8.24 s | 8.13 s | 63.45 s | 70.06 s |

端到端比值从 1.634× 降到 1.476×，模型流水线比值从 1.802× 降到 1.653×。Data-Juicer 每卡都有一次固定的 SAM2/GroundingDINO 和 HaMeR 加载，原始 receipt 记录两档 SAM2 加载约 11–15 秒、HaMeR 约 23–26 秒。EgoWorld 在常驻阶段中把模型准备重叠起来。批次扩大后，这部分重叠带来的相对收益收窄。EgoWorld 的清洗和导出合计从 20.96 秒增到 175.07 秒，占端到端时间的比例从 19.2% 升到 28.0%。筛选和导出的单位样本成本略降，墙钟占比仍因模型启动摊薄而上升。

把端到端比值写成模型流水线和其余墙钟的加权和，以 EgoWorld 墙钟占比为权重。对两档做对称分解，模型流水线的相对收益下降贡献约 −0.111×，流水线占比下降贡献约 −0.053×，其余阶段的相对耗时变化贡献约 +0.006×。这是已观测差距的算术归因。冷启动与样本分布的独立效应需要专门的重复试验才能分离。[两卡逐轮记录](benchmarks/v100-2026-11-09/two-gpu.json) · [864 张原始基准](benchmarks/v100-2026-11-09/endurance.json)

## 先处理 SAM2 的 CPU 解码

原 864 张长测中，两路 SAM2 工作进程的服务时间合计 802.65 秒。每个 clip 中位服务 0.918 秒、中位排队 4.089 秒。HaMeR 与 DexRetarget 的中位服务为 0.272 和 0.141 秒，排队中位数约 1 毫秒。SAM2 receipt 的中位进程 CPU 时间为 0.919 秒，与 0.905 秒的推理请求墙钟相近。SAM2 服务时间包含 GroundingDINO、视频准备和工作进程写出。

既有单卡独立留出集的 Nsight trace 中，CUDA kernel、拷贝及 memset 区间并集占 trace 的 3.93%（EgoWorld）和 4.79%（Data-Juicer）。两端主机与设备间分别搬运 9.85 GB 和 9.93 GB。该 trace 包含冷启动，提供了检查主机供给和同步的线索。864 张的瓶颈排序来自两卡阶段记录。[单卡 Nsight 汇总](benchmarks/v100-2026-11-09/profiling.json)

EgoWorld 的 SAM2 请求会对已准备视频探测元数据、准备提示帧，再由 SAM2 自身加载视频帧。OpenCV 4.11 的 FFmpeg 后端在本机默认给每个打开的短 clip 分配 16 个线程。对同批 50 个三帧视频做三轮解码对照，默认配置每次打开并解码用时约 38–39 毫秒，单线程约 17 毫秒。150 帧的像素 SHA-256 逐一匹配。复跑只给 EgoWorld 的 SAM2 进程设置 `OPENCV_FFMPEG_THREADS=1`。Data-Juicer、其他阶段进程和普通 benchmark 默认值沿用原配置。

若 Data-Juicer 重复原先的 921.29 秒，EgoWorld 需要低于 614.19 秒才能超过 1.5×，相较原墙钟需节省至少 10.19 秒。三次 OpenCV 打开在两条 SAM2 队列中摊开，按微测差值估计上限约 28 秒。排队与 CPU/GPU 重叠会影响实际墙钟。

本轮共 **29 分 38 秒**，含两臂运行、切换和逐值审计。两张 V100 分别为 0 和 2。等候四分钟后仍没有两张空闲卡，启动时两张各有至少 14.16 GiB 显存可用。

| 模型流水线 | 509.60 s | 818.13 s |
| 清洗筛选 | 113.60 s | 113.65 s |
| 校验与导出 | 66.39 s | 67.32 s |

本轮端到端收益为 **1.444×**，低于 1.5×。全部 870 个输入的清洗决定及拒绝原因一致。864 个 clip 的阶段表、数组、导出和 QC 逐值匹配，包括 2,592 条 mask 和每种导出的 2,694 行。计时结束后另做历史回验，优化版 EgoWorld 与原 864 张空闲长测的这些产物也逐值一致。

V100 2 的两臂 NVML 采样全部观察到外部计算。V100 0 的外部计算占 EgoWorld 采样的 502/1279、Data-Juicer 采样的 1457/1848。相较历史空闲配对，两臂的墙钟分别增加 73.17 秒和 86.08 秒，主要发生在模型流水线。单线程解码的收益来自同批像素等价微测，本轮共享配对无法隔离它对空闲卡墙钟的影响。相关回归测试 56 项通过，1 项按配置跳过。[机器可读复跑结果](benchmarks/v100-2026-11-09/endurance-followup.json)

## 复跑入口

从同一冻结计划复用所有 870 个条目及顺序，包括字节重复、黑白画面和坏视频。模型资产登记、独立标签和清洗规则沿用原 recipe，关闭结果缓存。下面的路径与物理 GPU 号用本地实际值替换。V100 服务器使用已有 Jammy 兼容层运行 Python。

```bash
python egoworld/scripts/benchmark_two_gpu.py --study output/endurance-followup freeze \
  --recipe "$FROZEN_RECIPE" --corpus "$FROZEN_CORPUS" --input-plan "$FROZEN_PLAN" \
  --devices 0,2 --sam2-decoder-threads 1
timeout --signal=INT --kill-after=12s 1782s \
  python egoworld/scripts/benchmark_two_gpu.py --study output/endurance-followup run \
    --coordinator "$SAM2_PYTHON" --dj-python "$DATAJUICER_PYTHON" \
    --layout stream-checked-dual --budget-seconds 1760
```

计时从每个框架入口开始，到所有产物提交及进程退出结束。外层上限覆盖两臂、切换和输出审计。逐值审计检查清洗决策与拒绝原因、阶段表、数组、导出、QC 和独立标签指标。NVML 记录两张 V100 的整卡利用率、显存和外部 CUDA 作业，便于分开解读共享与空闲测量。

## 100 TB 量级预估

预算应按进入模型的等价帧数与完整扫描的吞吐分别计算。设编码视频体积 100 TB（十进制），平均码率 20 Mbit/s，相当于约 11,111 小时素材。下表用已通过审计的历史空闲双卡 864 张结果作标尺，将 2,592 张处理帧的测量成本按等价帧数换算。按两张 V100 全天运行，包含历史标尺的清洗与导出成本。

| 进入模型的等价采样密度 | 等价帧数 | EgoWorld | Data-Juicer |
| --- | ---: | ---: | ---: |
| 0.5 帧/s | 2,000 万 | 56 天 | 82 天 |
| 2 帧/s | 8,000 万 | 223 天 | 329 天 |
| 5 帧/s | 2 亿 | 558 天 | 823 天 |

2 帧/s 情景中，仅模型流水线折算约 158 天和 261 天。一次顺序读取 100 TB 在有效吞吐 200 MB/s、500 MB/s、1 GB/s 下分别约为 5.79、2.31、1.16 天。原始视频是否要全解码、扫描是否可与模型重叠、采样与拒绝比例、连续镜头长度、分辨率、数据访问方式和输出尺寸都会改变总工期。模型可以收到 2 帧/s 的情景假定两端先形成同一采样输入。表中时间是静态三帧负载的情景换算。100 TB 的绝对交付时间需要用目标数据的分层样本重标定。

若在空闲卡上每 864 张能净省 10–28 秒，且 Data-Juicer 保持历史墙钟，2 帧/s 情景的 EgoWorld 工期约为 213–219 天，达标产出比约为 1.50–1.55×。这一条件预估用解码微测设定节省范围。按本轮共享实测换算，两端约为 249 天与 360 天，产出比为 1.444×。
