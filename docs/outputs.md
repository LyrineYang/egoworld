# 当前需求：已接入的模型与输出

范围已确认：先让已接入阶段可配置、可启动、可测试、可恢复；不新增硬件传感器、复杂模型或 Demo。
“已接入”表示有适配和写出代码；本地使用明确的模型替身测试数据流，真实 CUDA 推理仍需服务器测试。

## 五个处理阶段全部在需求内

| 阶段 / 组件 | 对应数据要求 | 输出文件 | 输入条件 |
| --- | --- | --- | --- |
| **SAM2.1 + GroundingDINO：分割与视频传播** | 手/物体类别、独立 mask、片段内对象 ID、二维框/中心轨迹、源帧与时间 | masks、instances、tracks.parquet | 普通 RGB 视频、文本提示、两套模型权重/配置 |
| **HaMeR：人手三维姿态** | 左右手、21 个关节点位置、手掌/手根朝向、手指关节旋转、手型参数、估计相机平移 | hand_pose.parquet | RGB、分割得到的手框、明确左右手、HaMeR 配套配置和 MANO 资产 |
| **FoundationPose：物体六维姿态** | 物体相对相机的位置和朝向及姿态轨迹 | object_pose.parquet | **已有**对齐 RGB-D、相机内参、带尺度网格；不要求新增硬件采集 |
| **DexRetarget：机器人手映射** | 指定机器人各关节的角度或位移序列、关节名称和单位 | mapping.parquet | 人手三维关节、目标机器人 YAML/URDF、左右手与坐标约定 |
| **Fast3R：相机和场景几何** | 抽样视图相机位置/朝向、内参、场景点云 | reconstruction.parquet、reconstruction-pointcloud.npz | 多帧 RGB；默认相对尺度与片段内参考系 |

SAM 属于核心视觉标注要求，既包括手也包括物体，不应仅作为“图像信息”略去。
GroundingDINO 提供文本检测框，SAM2 做分割与视频传播。当前使用 SAM2.1，不是 SAM3；本轮不更换模型。
“二维轨迹”是实例框中心序列，不是新增的 CoTracker/三维运动模型。

## 当前输出要求编号

| 编号 | 明确要求 | 来源 |
| --- | --- | --- |
| V1 | 每个手/物体的类别、片段内 ID 和逐帧 mask | GroundingDINO + SAM2 |
| V2 | 二维框、面积与中心轨迹 | SAM2 实例结果派生 |
| V3 | 所有逐帧结果与原视频帧号、时间戳对齐 | 全阶段 |
| H1 | 人手 21 个三维关节点，腕部相对坐标 | HaMeR |
| H2 | 手根/手指关节旋转、手型和估计相机平移 | HaMeR / MANO |
| O1 | 已满足 RGB-D/网格条件时的物体位置与朝向 | FoundationPose |
| R1 | 指定机器人手的关节角度/位移 | DexRetarget |
| S1 | 抽样帧的相机位姿、内参 | Fast3R |
| S2 | 有界采样场景点云 | Fast3R |

这些是现有 schema 3 对应的近期数据范围。普通 RGB 使用 rgb.json，启用 SAM2、HaMeR、DexRetarget、Fast3R；
有现成 RGB-D/网格时使用 full.json 加入 FoundationPose。各阶段仍可按实际需要关闭，依赖必须完整。

## 不加入本轮验收

原讨论中的接触力/扭矩/触觉（I2）、额外传感器采集、动作/接触新模型、机械臂控制、完整 SLAM/3DGS、
跨片段世界坐标融合均排除。命名的手指弯曲角、捏合距离、速度等派生指标也不作为当前启动门槛；
未来若需要，可基于现有结果单独补充，不阻塞本轮可用版本。

## 手部输出怎样读

| 当前表示 | 直观含义 |
| --- | --- |
| 21×3 关节点 | 手腕、各手指关节和指尖位置；不是 63 个关节 |
| 一个 3×3 根旋转 | 手根朝向 |
| 15 个 3×3 关节旋转 | 手指各段旋转；不是 135 个角度 |
| 10 个手型参数 | MANO 对手型的描述 |
| 三维相机平移 | 估计量，未标定时不保证真实场景尺度 |

人手关节旋转、按名称定义的弯曲角、机器人关节角是三种不同数据。当前保留前者和机器人映射，
不将矩阵字段重新命名为“食指弯曲度数”。HaMeR 使用模型先验尺度，Fast3R 默认相对尺度；
各表均有单位/参考系说明，但尚未建立统一世界坐标融合。

## 交付要求

用户按 [服务器操作说明](server.md)准备现有模型资产、复制配置、修改路径并启动；
预检失败应列出缺少的环境/文件；相同 run-id 可恢复，结果可读回并查看 QC。
代码必须覆盖启用阶段的真实 API 路径，本地必须通过契约、适配、启动和调度测试。
真实权重/显存/效果由服务器 smoke 补验证，不能将替身测试记成真实模型跑通。

字段类型唯一来源为 egoworld/contracts.py，使用 egoworld schema 查看。
