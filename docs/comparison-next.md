# 具身数据比较的下一轮交付

核心问题是：在相同输入、模型行为、完整输出与质量要求下，EgoWorld 能否比 Data-Juicer 产生更多有效具身数据，并减少时间、RAM/VRAM 和恢复成本。清洗效果和执行效率分开计量；契约有效行不能直接命名为高质量训练数据。

目前生产清洗/缓存与调度代码已经集成，297 项适用回归和短样例原生整链有独立记录。[既有 A 层 pilot](equal-work-benchmark.md) 是标注后的 CPU 清洗，不能代表完整产品。以下工作接续已有实现，不引入新模型或训练。

## 可立即使用的 B 层工程入口

`egoworld/scripts/verify_stage_datajuicer.py` 接受原生 `egoworld.worker` 保存的完整阶段 `request.json`，先通过原生 ModelActor，再通过真实 Data-Juicer DefaultExecutor + `egoworld_stage_mapper` 调用同一 runner 和 Writer。两边使用同一个外层解释器、配置、prepared clip、上游 receipts 和模型环境；没有把已有下游预测当成模型调用。

```bash
# 在仓库根目录；DJ_PY 指向固定 revision 的独立比较解释器。
. config.local/reproduction.env
.venv/bin/python egoworld/scripts/verify_stage_datajuicer.py \
  --request /absolute/native/.work/clip/dex_retarget/request.json \
  --python "$DJ_PY" \
  --output /mnt/d/EgoWorld/runs/comparison-prep/new-dex-check
```

外层比较环境沿用 [A 层固定版本](../egoworld/experiments/equal_work/requirements-pilot.txt)，另需 `opencv-python-headless==4.11.0.86`。该环境的 CPU Torch 只支持本次 CPU 阶段接入；GPU 模型应由配置中相同的 CUDA runner 执行，后续必须另外核验 Data-Juicer 的 GPU 资源声明与并发限制。不要升级已有模型环境。

该入口保存请求、输入/显式资产/生产源码哈希、前后包版本、Data-Juicer 配置与原始导出、日志、两端正式提交及审计。拒绝覆写目录、失效上游 receipt、临时 phase/cache 请求、空输出、数值变化、重复/缺失行和环境变化。完整逻辑字段与数值精确比较，忽略行序与 Parquet 序列化差异；数组逐值比较。输入在原处读取并前后校验，不是独立可分发的冻结语料库。

**它只是一阶段的小样例接入检查**，没有吞吐比值、独立质量评估或完整 recipe 调度。原生侧直接使用 ModelActor，不冒充生产 recipe；目前也没有证明 GPU 模型、Data-Juicer 多进程/批处理和完整依赖链可比较。需要数值容差的 GPU 任务，应先冻结重复原生运行的噪声、种子和判定标准，不能为了通过本入口临时放宽。隐式模型资产、外部 runner 源码与 GPU 资源身份还须纳入正式 B/C 冻结清单。

## 本次实际接入结果

真实 Data-Juicer DefaultExecutor 的左右手 Dex 均通过：每侧两端各 6 条机器人映射，全部逻辑字段与数值精确一致；输入/源码哈希和前后环境一致，原生模型重新执行，外部 runner 正常退出。阶段检查与既有 A 层门槛合计 31 项针对性测试通过，其中本次新增 8 项。详见 [机器可读验收](benchmarks/comparison-prep-2026-11-02.json)。

原始记录保留在 `/mnt/d/EgoWorld/runs/comparison-prep-20261102/`。首次准备脚本参数类型错误、缺少 OpenCV 的尝试，以及右手旧临时帧缓存引用被准入拒绝的日志均保留。右手另存移除该缓存引用的请求副本，两端读取同一副本；Dex 仅消费数值手姿态，不使用帧缓存。这些是接入准备问题，不是性能对照中的删失试验。

## 按结果验收的推进顺序

| 交付 | 固定项与验收门槛 | 可形成的结论 |
| --- | --- | --- |
| B1：逐模型原生对照 | 先 Dex 左右手；再 SAM/HaMeR、RGB-D FoundationPose、固定随机性的 Fast3R。每次验证相同帧、crop、权重、预处理、坐标、完整文件与拒绝原因；真实模型调用和 runner 退出有证据 | 适配接口等价，不能据此宣布速度或准确率更高 |
| B2：同模型执行比较 | 固定资源/并发和调参预算；Data-Juicer 默认及调优配置；冷 runner、热模型但结果 miss 分组；至少 5 次平衡顺序运行 | 导入、准备、推理、搬运和写出成本的可解释差异 |
| C1：实际产品任务 | RGB 手部→机器人、场景、RGB-D 物体/世界三组 recipes。两端同视频入口、清洗策略、依赖、QC、投影/世界导出与提交，计入所有入口成本 | 核心同输入/输出端到端有效产出与资源报告 |
| C2：复用与恢复 | 两端公平开放缓存；完整命中、部分失效、输入复用、指定位置中断/恢复分别成组，失败和重试保留在分母 | 重复处理和故障后的实际成本；不混入冷跑算法收益 |
| Q：清洗效果留出集 | 独立标注坏输入/手侧/遮挡/快速运动/无手但有场景价值等；开发集选阈值，固定留出集；复核随机保留和拒绝样本 | 按任务的误拒绝率、漏检率、有效覆盖与质量边界 |

正式语料应来自独立来源的 10–60 秒片段，并保留来源、许可、内容哈希和所有任务资产；RGB-D/mesh 单列。现有 3 秒 smoke、一个视频的 80 行及其重复运行只作工程夹具，不增加独立样本量。不得将手分支无效直接解释成场景分支也无用。

## 核心结果表与停止条件

每行至少保留：数据集/任务/独立视频数、输入数和固定采样覆盖、保留/拒绝及原因、有效输出数、入口到最终提交墙钟、有效产出/秒、进程树 RAM 和 GPU 显存观测方法、失败/OOM/重试、恢复重做量、逐字段一致性、质量误拒绝/漏检，以及配置/源码/资产/环境/原始运行记录。

预先定义缺行、空输出、非有限值、数值差异和质量门槛；任一端缺少计划运行或审计失败，保留原始结果但不给有效吞吐比值。按独立视频汇总分布和置信区间，不能把帧数当独立视频数。资源受其它进程竞争的组单列，计时边界一致。

只有 B/C 与留出集质量审计全部通过，才形成优于 Data-Juicer 的核心报告。已有内部调度消融和 A 层启动耗时继续作为解释材料，不替代这个结果。
